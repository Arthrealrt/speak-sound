# Speak Sound

Windows 11 本地中日 / 中英双向游戏语音翻译。中文麦克风 → 日语或英语合成 → 可选变声 → 本地试听 / 可选虚拟麦克风；队友日语或英语 → 中文 → 屏幕底部字幕与中文播报。虚拟麦克风发送可接游戏内置语音、Discord 等支持选择输入设备的软件，但仍需要兼容驱动。

**v0.8：独立语音双向翻译。** 顶部新增「仅双向翻译（不变声）」模式：中文直接生成所选日语 / 英语译音，保留虚拟麦克风发送和本地试听；队友语音仍生成透明中文字幕及可选中文播报。此模式完全绕过变声音效，即使之前选择了低沉、机器人等预设也不会应用。变声页暂时禁用，原来的音高、音效和启用设置会保留，切回其他模式后恢复使用。无需新增模型或驱动。

使用方法：顶部选择「仅双向翻译」，在设备页选好发送/接收语言及音频设备，再点击「开始双向翻译」。默认按住 F8 说中文、松开生成译音；目标游戏输入仍选择 Speak Sound Virtual Cable。只在本地使用时，可以关闭虚拟麦克风发送并开启外语试听。

**v0.7：透明双行字幕、接收人声筛选、英语双向语音。** 默认字幕无暗色底板，只显示中文，长句分页、最多两行，完整原文与译文保留在记录页。接收端加入本地 Silero VAD 和识别置信度/重复文本过滤；队友默认 240 ms 停顿、2.5 秒独立分段，只保留一条最新待处理语音。中文合成另用线程，静音时跳过合成，避免字幕等待播报。两种计算模式都取消温度回退重试；快速外语识别 beam 从 1 调至 2，均衡为 3，改善短句搜索范围。这些措施减少积压和异常识别，不保证任意游戏语音的速度或准确率。

这是开源 Python 桌面应用，按短句连续处理。识别使用 Whisper small，翻译使用 MIT 许可的 M2M100 418M，日语合成使用 OpenJTalk，中英合成使用各自 MIT 许可的 MeloTTS / sherpa-onnx 模型。音频不上传云服务，不需要 API Key；首次下载后可离线运行。组件许可见 [DEPENDENCIES.md](DEPENDENCIES.md)。

**v0.4 新增：** 指定运行进程接收（含子进程）、可调分段与停顿等待、快速计算预设与 CPU 线程数、中文播报和日语试听的独立实时音量及静音。新增 ProcTap（MIT）和 psutil（BSD），不需要新驱动或修改安全启动。

**v0.6：变声与双向翻译同时运行。** 默认链路为 `中文麦克风 → 识别 → 日语翻译 → 日语合成 → 变声 → 虚拟麦克风`，同时持续将队友日语转成底部中文字幕和中文播报。内置原声、低沉、明亮、卡通、机器人、电台预设，音高范围 -12～+12 半音，支持运行时调节及独立发送音量/静音。效果为本地 DSP，并非 AI 人物音色克隆或共振峰保持。开源 USB 虚拟声卡沿用 v0.5 后端。

顶部选择**功能模式及向游戏发送哪种声音**，三个模式均保留双向翻译：

| 发送方式 | 游戏 / Discord 收到 | 双向翻译 |
| --- | --- | --- |
| 仅双向翻译（不变声） | 中文翻译、合成后的日语或英语，不施加音效 | 我方译文与可选试听；队友中文字幕与可选中文播报 |
| 外语译音变声 | 中文翻译、合成并变声后的日语或英语 | 我方译文与可选试听；队友中文字幕与可选中文播报 |
| 原声实时变声 | 变声后的原语言，按 20 ms 块持续处理 | 我方原始麦克风同时识别翻译，显示日语并可本地试听；队友翻译持续运行 |

原声实时方式中，说中文仍向游戏发送中文；外语译音只在本地试听，避免两路声音在虚拟麦克风叠加。要让队友听到外语，请选择「仅双向翻译」或「外语译音变声」。原声只采集一次，先分流未变声的音频供识别，再进行音效处理。旧版实时变声设置自动迁移到同时翻译的原声发送方式。

**当前状态：本机已安装并加载签名 USB/IP 驱动，Secure Boot 保持开启。** Windows 已识别配对的虚拟扬声器和麦克风，并通过真实端点完成合成音变调收发验证；没有录制真人声音。新方案使用 BSD 开源 Virtual Cables 协议代码与 usbip-win2 签名发行版。其他机器仍需单独安装运输驱动；游戏 / Discord 和反作弊兼容性尚待实测。安装步骤及边界见 [驱动接入](drivers/README.md)。

## 安装

需要 Windows 11 x64、[Python 3.12 x64](https://www.python.org/downloads/windows/)。建议预留至少 8 GB 磁盘和 8 GB 可用内存。默认 CPU 可运行；速度需要在你的机器上实测。

在本目录打开 PowerShell：

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

可指定解释器或更小模型：

```powershell
.\setup.ps1 -PythonExe 'C:\Python312\python.exe' -WhisperModel base
```

安装脚本向项目 `.venv`、`models` 和 `bin` 部署依赖、模型和用户态声卡后端。后端用 Go 1.22+ 编译；没有 Go 时在项目 work 内下载、校验便携工具链，不改系统 PATH。默认不安装音频驱动、不改系统默认设备。`-SkipVirtualMic` 可跳过后端构建。依赖下载失败后重跑即可；模型下载可续传。模型目录不要提交到 GitHub。

安装完成双击 **`start.cmd`**。代码位于 `speak_sound/`，配置保存在本目录 `config.json`。目录需要可写。

已有 v0.6 安装只需更新源码并补充英语声库（约 163 MiB）：

```powershell
.venv\Scripts\python.exe tools\download_models.py --english-only
```

在「设备与字幕」页分别选择「我的中文翻译成」和「队友说的语言」，可独立选日语或英语。例如中文转英语发送、日语转中文接收也可同时运行。英语识别和文本翻译复用现有模型；英语合成使用固定版本的独立 MeloTTS English 声库，不经过日语引擎。词典外的游戏专名、缩写及数字读法仍可能不理想。

`setup.ps1` 使用 `requirements-lock.txt` 安装经过本机验证的确切依赖版本；`requirements.txt` 保留兼容版本范围供开发使用。

## 虚拟麦克风与设备连接

### v0.5 推荐路径：Speak Sound 虚拟 USB 声卡

1. 按 [drivers/README.md](drivers/README.md) 单独准备并安装签名开源 USB/IP 运输驱动。安装会短暂重启 USB 设备，需避开游戏、会议和文件传输。无需修改安全启动。
2. 在设备页点击「连接 Speak Sound 虚拟麦克风」，等待后刷新设备。
3. 本软件发送输出选 `扬声器 / Speakers (Speak Sound Virtual Cable 01)`，勾选「向虚拟麦克风发送声音」。
4. 游戏 / Discord 输入选 `麦克风 / Microphone (Speak Sound Virtual Cable 01)`，聊天输出保持耳机。
5. 顶部保持「日语译音变声」；在变声器页勾选启用并选择预设。按住 F8 说中文、松开后生成变声后的日语，同时持续接收队友翻译。选择原声实时发送时，F8 按住期间立即发送变声后的原语言，松开后提交日语翻译。

音高、附加音效、启用开关、发送音量和静音可运行时调整。两种发送方式均载入本地模型，保留队友翻译、指定进程接收、中文播报及日语试听；「仅接收队友语音」在两种方式均关闭自己的麦克风。原声实时监听另有独立开关，需在停止时设置。关闭应用或断开会关闭本软件虚拟声卡。实时本地监听必须戴耳机以避免啸叫，软件没有声学回声消除。

### 旧 RadioVoice 可选接入与本地试听

**无需虚拟驱动的本地播放：** 选择实体麦克风，接收来源选择「指定运行进程」并刷新选择 Discord 或游戏；也可选整个耳机 `[Loopback]`。在「译音播放」页选择耳机，保持中文播报与日语试听勾选。不要勾选「向虚拟麦克风发送日语」，即可同时听到两种译音，但日语不会传给队友。

**只收队友：** 勾选「仅接收队友语音」，不需要实体麦克风；可选择中文播报或仅看字幕。要真正发送到游戏，需准备下述驱动并启用「向虚拟麦克风发送日语」。

1. 先阅读 [开源驱动说明](drivers/README.md)。当前适配 GPL-3.0-or-later 的 RadioVoice 虚拟音频驱动；本项目不包含其二进制、不自动安装驱动、不更改启动安全设置。没有兼容驱动时，界面明确显示虚拟麦克风不可用。
2. 连接耳机，在本软件点击「刷新音频设备」。
3. 按下表选择设备：

| 位置 | 设置 | 示例 |
| --- | --- | --- |
| Speak Sound | 你的实体麦克风 | USB Microphone / 麦克风 |
| Speak Sound | 接收语音 | 你听队友语音的耳机对应 `[Loopback]` |
| Speak Sound | 日语输出 | **RadioVoice Output**（开源驱动的播放端） |
| 游戏 / Discord / 其他聊天软件 | 麦克风 / 输入 | **RadioVoice Microphone**（开源驱动的录音端） |
| 游戏 / Discord / 其他聊天软件 | 扬声器 / 输出 | 你的耳机 |

信号路径为 `RadioVoice Output → RadioVoice Microphone`：本软件写入播放端，对方软件从录音端读取。此路径须在用户自行准备好兼容驱动后联调，不代表本机已验证通过。

4. 目标聊天软件使用语音激活或持续输入。若目标软件也启用了按键说话，必须让它在**翻译日语播放期间**保持发送。只按住原文录音阶段不会传出译文。
5. 点击「开始翻译」，等待模型加载。默认**按住 F8 说中文，松开后翻译并播放日语**。也可关闭按键说话，自动检测讲话。F8 由 Windows 全局按键状态读取，不修改游戏文件。
6. 队友所选外语显示为底部中文字幕，默认隐藏原文、背景完全透明，白字带小范围阴影。设置里可调屏幕、字号、底部距离或勾选附带原文，并可预览。字幕窗口高度固定为最多两行；长句最多四页，新字幕会替换旧分页，避免继续堆积。完整文本在记录页查看，仅在内存中保留最近 300 个文本块。

## 译音播放与虚拟扬声器

「译音播放」页提供两个独立开关：队友外语转中文播报、自己中文转所选外语后的本地试听。它们使用现有耳机或扬声器，无需内核驱动。两种本地声音串行播放，最多排队两句；积压时跳过新的试听。中文合成独立于字幕识别线程，静音/中文音量为零时不生成中文播报；已排队的静音音频也不会触发回声暂停。停止会丢弃未播放内容。

窗口底部两个音量滑条分别控制中文播报和我方试听（包含日语译音及可选原声实时监听），范围 0～100%，运行中即时生效；「静音本地译音」同时静音本地声音。这些控制只调节本软件的本地声音，不改系统音量，也不影响虚拟麦克风发送的音量。

只选择耳机播放不会创建系统设备。v0.5 设备页的连接按钮通过开源 USB/IP 后端创建配对的虚拟播放端与麦克风端；Windows 音频类驱动由系统提供，USB 运输层来自上游签名发行版。实际状态和安装说明见 [drivers/README.md](drivers/README.md)。窗口下方的虚拟麦克风发送音量/静音与本地监听独立。

回声保护：指定进程模式只采集目标及其子进程的播放声音，不会采集本软件译音，译音播放时继续接收队友。整个设备模式在本地译音播放期间及结束后约 0.3 秒暂停接收，以避免循环翻译，可能漏收重叠讲话。两种模式均暂停此时的实体麦克风采集；这不是声学回声消除，建议戴耳机。

## 选择运行进程接收

在「设备与字幕」中将「接收来源」改为「指定运行进程」，点击「刷新进程」，从列表选择名称和 PID，可输入名称筛选。Discord 等多进程软件优先选择主进程，采集包含其子进程，音频不受目标播放设备选择影响。整个设备模式仍使用下方回环设备。

进程列表仅保存于内存，每次启动需重新选择。目标退出、PID 被重用或进程接口失败会停止并提示；不会悄悄回退为整机录音。为防止译音循环，列表排除本软件及其祖先进程。部分受保护进程或音频内容可能无法采集，此时可手动选择设备回环。此功能使用 Windows 11 自带的 WASAPI Process Loopback，不注入游戏进程、不安装驱动。

## 调整翻译速度

「速度与延迟」页可在停止后调整，下次开始生效：

| 控件 | 范围 / 作用 |
| --- | --- |
| 停顿等待 | 100～1500 ms；自然讲话停顿后多久提交 |
| 连续讲话最长分段 | 1～10 秒；长句达到此长度立即处理 |
| 队友停顿等待 / 最长分段 | 100～1500 ms / 1～6 秒；默认 240 ms / 2.5 秒，独立于我方分句 |
| 计算模式 | 均衡：中文识别 beam 5、外语 beam 3、翻译 beam 4；快速：中文 beam 3、外语 beam 2、翻译 beam 2；均禁用温度回退重试 |
| 识别 CPU 线程数 | 1～16；占用更多线程可能加速，也会争用游戏 CPU |
| 低延迟预设 | 200 ms / 3 秒 / 快速 / 最多 8 线程（不超过逻辑核心数的一半） |
| 均衡预设 | 400 ms / 5 秒 / 均衡 / 4 线程 |

按住 F8 讲话后松开会立即提交，不再额外等待设定的停顿。更短等待和分段可能切断自然停顿、减少上下文，快速搜索也可能降低准确率。这些设置控制分句和计算策略，不能保证总延迟；总耗时还包括识别、翻译、合成、排队和播放。

v0.4 历史测试中，4 个合成短句各重复 2 次，快速预设的识别+翻译平均约 1.06 秒，均衡约 1.19 秒；这不是 v0.7 新路径的性能承诺。v0.7 的中日英小样本及非人声检查见 [VALIDATION.md](VALIDATION.md)，均不包含录音、停顿等待和排队，不能代表游戏中的完整延迟。

### 减少游戏音效干扰

「接收人声筛选」默认标准模式：在 WebRTC VAD 分句之后，用随 faster-whisper 安装的 MIT Silero ONNX 模型再次筛选，非语音片段不进入 Whisper；再拒绝低置信度、异常重复或与音频时长明显不符的识别文本。严格模式提高门槛，适合音效误触发较多时使用，但可能漏掉很短、很轻的队友报点；关闭模式仅关闭神经网络检测，仍保留异常文本过滤。没有新增云服务。

**这不是队友身份识别或声源分离。** 对 Apex、PUBG、ARC Raiders、Warzone / Call of Duty 等游戏，如果内置聊天与游戏音效已经混音，单选游戏进程仍会收到全部混合声音，角色对白也属于人声。若游戏设置提供独立的语音聊天输出，把它送到另一个已有音频设备并选择其回环；是否提供该设置需按游戏和版本检查。本软件不注入游戏，也不能从同一进程中凭空拆出聊天音轨。使用独立 Discord 等软件时，选择聊天进程可以排除其他游戏进程的声音。

设备回环捕获该设备的**全部声音**；指定 Discord 进程可排除其他游戏和系统声音。如果语音与游戏音效来自同一个游戏进程，按进程采集仍包含两者，不能自动分离。也可使用另一块实体声卡或独立耳机作为聊天输出，再监听其回环。不要把发送用的虚拟播放端同时用作接收端。

如果游戏只提供合并后的声音，首版无法可靠提取单独的队友声音。戴耳机，避免实体麦克风拾取耳机漏音。日语译音发送方式在日语发送期间暂停本机麦克风采集，防止回授；两种方式在本地译音播放期间也会暂停麦克风，可能漏收此时讲话。不要将发送音频线监听回接收总线。

| 接收神经网络语音检测 | Silero VAD / ONNX Runtime，MIT | 本机 CPU，复用 faster-whisper 随包模型 |
| 虚拟音频端点适配 | RadioVoice GPL 驱动 | 需另行准备，尚未本机验证 |
| v0.5 虚拟 USB 声卡 | BSD 用户态后端 + BSD usbip-win2 签名运输驱动 | 本机实际端点已通过合成音验证，其他机器需单独安装运输驱动 |
| v0.5 实时变声 | NumPy / SciPy DSP，不需新模型 | 本机 CPU，直接处理麦克风 / 日语译音 |

我方默认停顿约 400 ms 后提交、连续讲话约 5 秒分段；队友默认 240 ms / 2.5 秒，可分别调整。最短有效讲话约 160 ms，严格检测要求更长。保留约 200 ms 前导音频，减少切掉字头。长句分段可能影响翻译上下文。发送最多排队两句；接收只保留最新一条待处理语音，拥堵时丢弃旧的等待片段，不中断已经开始的推理。识别和翻译模型分别加锁，双向共享模型节省内存；繁忙时两个方向可能相互等待。记录中的耗时只包含识别与翻译，不包含录音、分句等待、排队、语音合成和播放，不代表完整端到端延迟。

更快识别可运行 `setup.ps1 -WhisperModel base`（同一个 `models/whisper` 目录会切换模型）；更高精度可选 `medium` 或 `large-v3-turbo`。下载失败时不要启动，重跑直到完成。运行期严格使用本地文件；缺失模型会显示错误，不会悄悄调用在线服务。CPU 为默认部署，不会自动安装 CUDA 或占满显卡。

本版使用 CPU 推理，不需要另装专有 GPU 计算库。内置 OpenJTalk 的音色偏机械；Mei 声库采用 CC BY 3.0，署名见 [DEPENDENCIES.md](DEPENDENCIES.md)。中文 MeloTTS 浮点 ONNX 模型约 170 MB，保存在 `models/chinese-tts`。翻译模型、分词器分别位于 `models/m2m100` 和 `models/m2m100-tokenizer`；旧版模型不再加载。

## 常见问题

- **游戏全屏看不到字幕：** 使用无边框窗口或窗口模式。独占全屏可能覆盖桌面置顶窗口。字幕穿透鼠标，不抢游戏焦点。
- **对方听不到：** 先连接虚拟声卡，本软件选 Speak Sound Virtual Cable 播放端，聊天输入选其麦克风端（旧 RadioVoice 使用其配对端点），并确保实际声音播放时允许发送。当前未验证完整游戏链路。
- **识别到游戏台词或音乐：** 若聊天与游戏是不同进程，选聊天进程；同一个游戏进程混音仍需独立音频路由，语音检测不能自动区分队友、配音和其他人声。
- **进程重启后不再接收：** 停止后刷新进程，重新选择新的 PID 再开始，不会自动录制同名的新进程。
- **设备失效：** 停止、重新连接设备、刷新并重选。设置按设备名称保存，设备更名后需重选。
- **F8 无效：** 检查游戏是否占用或拦截该键；通常不需要管理员权限。
- **停止稍慢：** 停止会中断后续采集与播放，等待已经开始的模型计算结束，然后释放音频设备。
- **运行报错：** 从终端执行 `.venv\Scripts\python.exe -m speak_sound` 查看完整输出。

## 验证

本次实际验证范围和模型输出见 [VALIDATION.md](VALIDATION.md)。

```powershell
.venv\Scripts\python.exe -m unittest discover -s tests -v
.venv\Scripts\python.exe -m compileall -q speak_sound tools tests
.venv\Scripts\python.exe tools\verify_local.py
```

`verify_local.py` 不录制麦克风：列举设备，使用本地模型翻译两句中日文，合成日语并回识别，最后保存检查结果到本机 `verification.json`。它不验证游戏服务器是否实际收到语音。最终需要实际连接虚拟音频线并和队友测试，调整音量、降噪、延迟与识别模型。

可选执行 `.venv\Scripts\python.exe tools\verify_process_audio.py --run`，用两个自建进程播放约 5 秒低音量测试音并核对隔离效果；会有测试音，不录麦克风、不保存真实软件声音。
